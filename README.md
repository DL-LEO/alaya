# Alaya（识海）技能说明书

> 一个共享知识库，每个角色检索方式不同；通过熏习，知识变成智慧。
> 纯 Markdown + JSON，无向量库、无 embedding、无 API Key。

| 项目 | 内容 |
|---|---|
| 中文名 / 英文名 | 识海 / Alaya（Personified Multi-Role Knowledge Memory System） |
| 当前版本 | 3.1.0（配置项：knowledge 3.0.0、memory 2.0.0、persona 2.0.0、import 2.0.0、maintenance 2.0.0） |
| 开源协议 | Apache-2.0 |
| 实现语言 | Python（核心功能仅依赖标准库） |
| 技能安装目录 | 例：`C:\Users\sjlia\.workbuddy\skills\alaya` |
| 用户知识库 | 例：`D:\alaya-kb`（初始化时由用户决定） |
| 组成 | 1 个主技能 + 5 个子技能 + 18 个可执行脚本 + 6 个内部库模块 + 8 个内置角色 |

主分支（设计主文档）：https://gitee.com/DL-LEO-gitee/alaya/tree/master/

## 一、它是什么：从「识」到「智」

### （一）核心命题

唯识学中的「转识成智」，是把八识转成四智的终极转化。Alaya 借用这个框架做知识管理：知识库里被静态存放的内容只是「识」，只有被不同视角反复执取、追问、使用，才逐步变成「智」。

| 层次 | 含义 |
|---|---|
| 识 | 存储的知识，被动检索，扁平 |
| 智 | 活的知识，多视角，持续生长 |

因此 Alaya 把你的知识库当成一座活的种子库（bīja）：种子会生长、会衰减、会互相关联、会演化。多个角色（末那识）从不同角度执取同一批种子，通过反复熏习（xunxi），把原始的知识逐渐转化为有视角的智慧。

> 需要说明：这是设计隐喻，不是技术承诺。Alaya 实际提供的是「总索引 → 类别索引 → 知识卡」的三层描述驱动检索网络，不宣称具备完整的知识图谱推理引擎。

### （二）唯识概念与系统机制的对应

| 唯识概念 | Alaya 机制 | 如何转化知识 |
|---|---|---|
| 阿赖耶识（藏识） | 活种子系统 | 每张卡片有 `strength`，被引用则增强，长期不用则衰减；种子不是静态的 |
| 末那识（执取） | 多角色检索 | 8 个内置角色各有兴趣焦点，同一知识被从不同角度执取，视角由此涌现 |
| 第六意识（分别） | 按角色 LLM 推理 | 每个角色用自己的声音推理：费曼简化、苏格拉底追问、佛祖升华 |
| 熏习（反复修行） | 三级自动维护 | 每次交互留下痕迹：种子增强、好感网络生长、角色进化 |
| 种子衰变（无常） | 自然遗忘与休眠 | 不用的知识褪色进入休眠，不是删除而是修剪；话题重提时可被唤醒 |
| 两印法（质量门控） | 来源追溯（已落地）+ 共识校验（理念） | 每张卡片记录来源文件或原始路径，来源不可用时如实说明；「共识印」目前仍是设计理念，未实现为独立校验 |

### （三）与其他方案的差别

| 维度 | 常规 RAG | 静态 Wiki | Agent 内置记忆 | Alaya |
|---|---|---|---|---|
| 角色个性 | 无 | 单一 | 单一 | 多角色，可切换 |
| 知识生长 | 静态 | 手动 | 手动 | 使用即增长 |
| 可追溯性 | 弱 | 无 | 无 | 来源锚点 + 卡片路径 |
| 遗忘机制 | 硬删除 | 无 | 窗口丢弃 | 自然衰减 + 休眠唤醒 |
| 情感层 | 无 | 无 | 无 | 角色好感网络 |
| 依赖 | 向量数据库 | 无 | 绑定特定产品 | 无（纯文件，任意有文件系统的 Agent） |

## 二、用来干什么

| 场景 | 用户怎么说 | 系统做什么 |
|---|---|---|
| 角色化问答 | 「费曼，你怎么看 attention 机制？」 | 检索相关知识 + 按角色视角作答，答后固定提交一次记忆 |
| 同题多视角 | 「苏格拉底，你怎么看同一个话题？」 | 同一批知识，完全不同的切入口与追问方式 |
| 多角色研讨 | 「让费曼、荣格和 BI 讨论这个方案」 | 各自独立出观点 → 指出一致与分歧 → 主持人汇总 |
| 知识检索 | 「查一下我知识库里有没有这个主题」 | 三层检索，区分「知识库事实 / 模型推断 / 信息缺口」 |
| 资料入库 | 「把这批资料导进知识库」 | 批量导入，先零写入预览，确认后串行提交 |
| 单篇收录 | 「把这篇文章收录一下」 | 生成完整知识卡，脚本负责元数据、去重与索引 |
| 长期偏好 | 「记住我喜欢先给结论再讲原因」 | 确认后写入共享偏好档案，跨角色复用 |
| 知识库维护 | 「检查知识库」「现在熏习一次」 | 只读健康检查 / 链接审计 / 衰减结算 |

**不适合做什么**：不做联网下载（URL 内容由宿主智能体先取回）、不做完整知识图谱推理、不做向量语义检索、不做权限与加密管理、不替代用户判断知识真伪。

## 三、工作原理

从「识」到「智」是一条四段流水线，每一段对应一个唯识概念：

```text
用户提问
   │
   ▼
① 阿赖耶识（种子库）
   · wiki/index.md → {类别}_category.md → 卡片内容
   · 问题驱动检索：把问题匹配到相关类别（不涉及角色）
   · 这是「识」：原始的、未分化的知识
   │
   ▼
② 末那识（执取引擎）
   · 每个角色用自己的 interest_foci 过滤候选池
   · 费曼看到「物理直觉」，苏格拉底看到「能质疑什么」
   · 这是转折点：识开始转化
   │
   ▼
③ 第六意识（分别表达）
   · LLM 以角色独特的声音推理
   · 回答带视角 + 来源锚点（可追溯）
   · 这是果实：有视角的知识 = 早期的「智」
   │
   ▼
④ 熏习（反复修行）
   · 种子增强、好感加深、视角锐利
   · 循环重复，识 → 智，一步一步
```

工程上这条链路没有任何外部依赖：没有向量数据库、没有 embedding、没有 API Key，全部是文件系统上的 Markdown + JSON。

## 四、架构

### （一）双区分离：技能与用户数据彻底分开

这是当前实现的第一原则：技能是程序，知识库是用户资产。技能可下载、覆盖、升级；`alaya/ wiki/ raw/` 三棵树由用户拥有，升级绝不覆盖。

```text
技能安装目录（可下载、可覆盖升级）
├─ SKILL.md          主技能：意图识别与路由
├─ skills/           5 个子技能，按需加载
├─ scripts/          18 个可执行脚本 + lib/ 6 个内部模块
├─ manas/            8 个内置角色种子
├─ config/           默认配置
└─ templates/        卡片与角色模板

用户知识库（用户拥有，升级不覆盖）
├─ alaya/            配置、角色、私有记忆、共享记忆、BI 观察
├─ wiki/             类别目录、知识卡、总索引与类别索引
└─ raw/              用户本次明确选择保存的原文副本
```

知识库根目录解析优先级：命令行 `--kb-root` > 环境变量 `ALAYA_PATH_FILE` > 用户主目录 `.alaya_path` > 当前目录本身含 `alaya/config.json`。**永不允许回退到技能安装目录**，避免把程序目录当数据仓库。

### （二）主技能 + 5 子技能

v3.0 把原本约 40KB 的单体技能拆成「轻量主技能 + 5 个按需加载的子技能」，初始上下文占用下降约 80%。主技能只做三件事：初始化、意图路由、版本协调。

| 子技能 | 负责什么 | 典型触发 |
|---|---|---|
| `alaya-persona` | 角色选择、复制、回收、群组讨论、统一语言 | 「用费曼回答」「让几个角色讨论」「所有角色都用中文」 |
| `alaya-retrieval` | 总索引、类别索引、知识卡与交叉链接检索 | 「查我的知识库」「结合知识库解释」 |
| `alaya-import` | 批量导入、单篇收录、语义知识卡、质量检查 | 「导入这些资料」「收录这篇文章」 |
| `alaya-memory` | 回答后固定提交、共享状态与历史、用户档案、BI 观察 | 「记住这个偏好」「忘掉职业信息」 |
| `alaya-maintenance` | 动态索引、链接检查、衰减熏习、健康检查 | 「检查知识库」「预览重建索引」 |

激活模式为 `contextual`（上下文触发）：只有用户明确提到 Alaya、角色、知识库、记忆、导入、检索或维护意图时才介入，普通闲聊与通用问答不自动接管。

### （三）三层描述驱动知识图谱

```text
Layer 1 · wiki/index.md（约 1–2KB）
  类别 wikilink + 描述段落；LLM 读此文件把问题与类别做语义匹配

Layer 2 · wiki/{类别}/{类别}_category.md
  类别头部描述 + 「## Cards」区（卡片名 + 一行描述）；构建候选池

Layer 3 · wiki/{类别}/*.md
  知识卡本体，YAML 头含 description 字段；仅在角色选中后加载全文
```

关键设计：**描述本身就是图谱**。系统不再维护显式图边与标签交叠计算，跨类别关系以散文写进描述（如「与认知科学在注意力概念上交叉」），由 LLM 语义匹配自然发现。三层全部使用 `[[wikilinks]]`，因此知识库可直接作为 Obsidian vault 打开，用 Graph View 看到卡片与交叉引用。

### （四）知识卡格式

```markdown
---
seed_type: REFINED
created_by: system
strength: 0.5
last_activated: 2026-05-31
activation_count: 0
half_life: 30
tags: [deep-learning, transformer, attention]
description: "Transformer 架构通过自注意力机制实现了序列到序列的高效建模。"
---

# Transformer Architecture

正文内容……
```

卡片身份是「类别路径 + 文件名」，不是显示标题；内容哈希相同即视为重复，同名不同内容会生成稳定后缀，绝不覆盖旧卡。

### （五）核心机制

| 机制 | 作用 |
|---|---|
| 描述驱动检索 | 三层语义匹配替代显式图边与标签计算 |
| 卡片 description | YAML 中的一行摘要，让第二层无需加载全文即可匹配 |
| 类别头描述 | 从类别页的自动区块提取为索引摘要，可让智能体按「更新类别描述」重写 |
| 角色档案 | JSON 配置 + Markdown 人物小传（核心特质、说话习惯、对话示例） |
| 熏习 | 被引用则增强、长期不用则衰减；按日结算并去重 |
| 休眠与唤醒 | 低于阈值进入休眠并提示；话题重提时以基础强度唤醒 |
| 来源追溯 | 卡片记录来源文件或原始路径；原文缺失时明确标注，不伪造引用 |
| BI 观察员 | 被动观察需求、决策、表达、兴趣、协作、风险六方面，只观察不干预 |

### （六）记忆层：分层且有边界

| 文件 | 内容 | 边界策略 |
|---|---|---|
| `memory/<persona>_memory.json` | 角色私有记忆 | 仅该角色可见 |
| `memory/ambient.json` | 跨角色轻量近期环境 | 上限 64KB |
| `memory/shared/profile.json` | 经用户确认的稳定偏好 | 上限 128KB，冲突需确认替换 |
| `memory/shared/state.json` | 跨角色当前有效状态 | 上限 128KB，按主题覆盖而非追加 |
| `memory/shared/history.json` | 重要变化历史 | 热 20 / 冷 80 / 512KB，超限裁剪最旧 |
| `memory/bi_state.json`、`bi_notes.json` | BI 观察结论与事件 | 每域 20 条、总 200 条、180 天、状态文件不超过 256KB |

固定保存时机是**每次角色回答完成后**与**每次群组汇总完成后**，不猜测「会话是否即将结束」。写入使用唯一 `turn_id` / `group_id`，重试幂等：不重复增强卡片、不重复增长好感、不重复写记忆。

### （七）关键参数（`alaya/config.json`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `knowledge.top_k` / `min_pool` | 3 / 10 | 默认取卡片数 / 候选池下限 |
| `knowledge.cold_after_days_default` | 90 | 卡片进入休眠的天数 |
| `knowledge.wake_strength` / `sleep_threshold` | 0.5 / 0.1 | 基础强度 / 休眠阈值 |
| `memory.hot_zone_size` / `cold_zone_size` | 5 / 45 | 记忆热区 / 冷区容量 |
| `memory.semantic_memory_enabled` | true | 是否启用回答后简短语义记忆 |
| `persona.default_persona` | feynman | 默认角色 |
| `persona.language_mode` | global | 统一语言（改顶层 `language` 一处生效） |
| `persona.affinity_decay` | 0.992 | 角色好感每日衰减 |
| `import.max_chars_for_extraction` | 8000 | 单文件抽取字符上限 |

关于衰减的两代口径：v2.x 采用「30 天半衰期」，约 67 天进入休眠；v3.1 收敛为唯一主参数「90 天从 0.5 衰减到 0.1」，每日衰减率由 `d = (0.1 / 0.5)^(1/90)` 反推，不再叠加互相矛盾的固定衰减率。首次升级只建立当天基线，不追溯补扣。

## 六、常用命令：直接说中文就行

> 不需要记任何命令、不需要打开命令行。你只要把想要的结果说清楚，智能体会自己挑动作、自己调用工具。下面是可直接照说的一句话。

### （一）第一次使用

| 你这样说 | 它会做什么 |
|---|---|
| 「启用识海」或「初始化 Alaya」 | 引导你选硬盘、定目录、决定要不要装内置角色，然后建好知识库 |
| 「检查一下装好了没」 | 自检技能文件是否完整，缺什么会直接告诉你 |
| 「所有角色以后都用中文」 | 统一改一次语言设置，不用逐个角色去调 |

### （二）日常问答与检索

| 你这样说 | 它会做什么 |
|---|---|
| 「用费曼解释这个概念」 | 挑出相关知识，用费曼的口吻和思路回答 |
| 「让费曼、荣格和小昭讨论这个方案」 | 三个人各自出观点，再给你一份分歧与共识的汇总 |
| 「查知识库里关于世界模型的资料」 | 按索引逐层检索，回答里标明信息来自哪张卡片 |
| 「列出我有哪些角色」 | 列出当前知识库里的角色清单 |
| 「把每次检索的资料改成五条」 | 调整检索深度（术语是 top_K），以后默认取五条 |

### （三）把资料收进知识库

| 你这样说 | 它会做什么 |
|---|---|
| 「把这批资料导进知识库」 | 批量导入，先给你一份零写入预览，你点头才真正落库 |
| 「把这篇文章收录一下」 | 单篇收录，生成一张完整知识卡 |
| 「帮我整理成知识卡」 | 它先读懂内容，再按卡片格式整理，而不是机械搬运原文 |
| 「这次把原文也存一份」 | 只有你这么说，才会把原文复制进知识库的原文目录 |
| 「检查这批卡片的质量」 | 只读体检：缺描述、缺来源、内容过短的卡片会被点出来 |

导入时它一定会追问一句：这次要不要把原文也存进知识库。这是每次都要单独回答的问题，不会沿用上次的选择。

### （四）记忆与偏好

| 你这样说 | 它会做什么 |
|---|---|
| 「记住我喜欢先给结论，再讲原因」 | 确认后写进共享偏好档案，所有角色都照着办 |
| 「你还记得我哪些偏好？」 | 列出已确认的偏好清单，附上来源与时间 |
| 「忘掉我的职业信息」 | 删掉这条偏好和它的变化记录 |
| 「这次不用记」 | 本轮对话不写记忆，只更新必要的机械状态 |
| 「以后别主动问我建档案」 | 记下拒绝状态，不再反复打扰 |

### （五）检查与维护

| 你这样说 | 它会做什么 |
|---|---|
| 「检查知识库」 | 只读体检：配置、角色、卡片、索引、原文引用、链接逐项过一遍 |
| 「预览重建索引」 | 先告诉你索引和磁盘差在哪，不动任何文件 |
| 「确认重建索引」 | 真的重建，并保证总索引覆盖全部类别 |
| 「检查坏链接」 | 只列报告，不擅自改你的文件 |
| 「修复链接的大小写错误」 | 只修那些唯一确定、不会误伤的链接 |
| 「现在熏习一次」 | 立刻结算一次知识强度与角色好感；平时它每天自己顺带做 |
| 「审视一下分类结构」 | 观察员角色检查类别是否过碎，给出合并建议 |

进阶说明：上面每一个说法背后都有对应的脚本命令，需要排查问题、写自动化任务时可以让智能体直接执行；日常使用则完全不必接触命令。

## 一、它是什么：从「识」到「智」

### （一）核心命题

唯识学中的「转识成智」，是把八识转成四智的终极转化。Alaya 借用这个框架做知识管理：知识库里被静态存放的内容只是「识」，只有被不同视角反复执取、追问、使用，才逐步变成「智」。

| 层次 | 含义 |
|---|---|
| 识 | 存储的知识，被动检索，扁平 |
| 智 | 活的知识，多视角，持续生长 |

因此 Alaya 把你的知识库当成一座活的种子库（bīja）：种子会生长、会衰减、会互相关联、会演化。多个角色（末那识）从不同角度执取同一批种子，通过反复熏习（xunxi），把原始的知识逐渐转化为有视角的智慧。

> 需要说明：这是设计隐喻，不是技术承诺。Alaya 实际提供的是「总索引 → 类别索引 → 知识卡」的三层描述驱动检索网络，不宣称具备完整的知识图谱推理引擎。

### （二）唯识概念与系统机制的对应

| 唯识概念 | Alaya 机制 | 如何转化知识 |
|---|---|---|
| 阿赖耶识（藏识） | 活种子系统 | 每张卡片有 `strength`，被引用则增强，长期不用则衰减；种子不是静态的 |
| 末那识（执取） | 多角色检索 | 8 个内置角色各有兴趣焦点，同一知识被从不同角度执取，视角由此涌现 |
| 第六意识（分别） | 按角色 LLM 推理 | 每个角色用自己的声音推理：费曼简化、苏格拉底追问、佛祖升华 |
| 熏习（反复修行） | 三级自动维护 | 每次交互留下痕迹：种子增强、好感网络生长、角色进化 |
| 种子衰变（无常） | 自然遗忘与休眠 | 不用的知识褪色进入休眠，不是删除而是修剪；话题重提时可被唤醒 |
| 两印法（质量门控） | 来源追溯（已落地）+ 共识校验（理念） | 每张卡片记录来源文件或原始路径，来源不可用时如实说明；「共识印」目前仍是设计理念，未实现为独立校验 |

### （三）与其他方案的差别

| 维度 | 常规 RAG | 静态 Wiki | Agent 内置记忆 | Alaya |
|---|---|---|---|---|
| 角色个性 | 无 | 单一 | 单一 | 多角色，可切换 |
| 知识生长 | 静态 | 手动 | 手动 | 使用即增长 |
| 可追溯性 | 弱 | 无 | 无 | 来源锚点 + 卡片路径 |
| 遗忘机制 | 硬删除 | 无 | 窗口丢弃 | 自然衰减 + 休眠唤醒 |
| 情感层 | 无 | 无 | 无 | 角色好感网络 |
| 依赖 | 向量数据库 | 无 | 绑定特定产品 | 无（纯文件，任意有文件系统的 Agent） |

## 二、用来干什么

| 场景 | 用户怎么说 | 系统做什么 |
|---|---|---|
| 角色化问答 | 「费曼，你怎么看 attention 机制？」 | 检索相关知识 + 按角色视角作答，答后固定提交一次记忆 |
| 同题多视角 | 「苏格拉底，你怎么看同一个话题？」 | 同一批知识，完全不同的切入口与追问方式 |
| 多角色研讨 | 「让费曼、荣格和 BI 讨论这个方案」 | 各自独立出观点 → 指出一致与分歧 → 主持人汇总 |
| 知识检索 | 「查一下我知识库里有没有这个主题」 | 三层检索，区分「知识库事实 / 模型推断 / 信息缺口」 |
| 资料入库 | 「把这批资料导进知识库」 | 批量导入，先零写入预览，确认后串行提交 |
| 单篇收录 | 「把这篇文章收录一下」 | 生成完整知识卡，脚本负责元数据、去重与索引 |
| 长期偏好 | 「记住我喜欢先给结论再讲原因」 | 确认后写入共享偏好档案，跨角色复用 |
| 知识库维护 | 「检查知识库」「现在熏习一次」 | 只读健康检查 / 链接审计 / 衰减结算 |

**不适合做什么**：不做联网下载（URL 内容由宿主智能体先取回）、不做完整知识图谱推理、不做向量语义检索、不做权限与加密管理、不替代用户判断知识真伪。

## 三、工作原理

从「识」到「智」是一条四段流水线，每一段对应一个唯识概念：

```text
用户提问
   │
   ▼
① 阿赖耶识（种子库）
   · wiki/index.md → {类别}_category.md → 卡片内容
   · 问题驱动检索：把问题匹配到相关类别（不涉及角色）
   · 这是「识」：原始的、未分化的知识
   │
   ▼
② 末那识（执取引擎）
   · 每个角色用自己的 interest_foci 过滤候选池
   · 费曼看到「物理直觉」，苏格拉底看到「能质疑什么」
   · 这是转折点：识开始转化
   │
   ▼
③ 第六意识（分别表达）
   · LLM 以角色独特的声音推理
   · 回答带视角 + 来源锚点（可追溯）
   · 这是果实：有视角的知识 = 早期的「智」
   │
   ▼
④ 熏习（反复修行）
   · 种子增强、好感加深、视角锐利
   · 循环重复，识 → 智，一步一步
```

工程上这条链路没有任何外部依赖：没有向量数据库、没有 embedding、没有 API Key，全部是文件系统上的 Markdown + JSON。

## 四、架构

### （一）双区分离：技能与用户数据彻底分开

这是当前实现的第一原则：技能是程序，知识库是用户资产。技能可下载、覆盖、升级；`alaya/ wiki/ raw/` 三棵树由用户拥有，升级绝不覆盖。

```text
技能安装目录（可下载、可覆盖升级）
├─ SKILL.md          主技能：意图识别与路由
├─ skills/           5 个子技能，按需加载
├─ scripts/          18 个可执行脚本 + lib/ 6 个内部模块
├─ manas/            8 个内置角色种子
├─ config/           默认配置
└─ templates/        卡片与角色模板

用户知识库（用户拥有，升级不覆盖）
├─ alaya/            配置、角色、私有记忆、共享记忆、BI 观察
├─ wiki/             类别目录、知识卡、总索引与类别索引
└─ raw/              用户本次明确选择保存的原文副本
```

知识库根目录解析优先级：命令行 `--kb-root` > 环境变量 `ALAYA_PATH_FILE` > 用户主目录 `.alaya_path` > 当前目录本身含 `alaya/config.json`。**永不允许回退到技能安装目录**，避免把程序目录当数据仓库。

### （二）主技能 + 5 子技能

v3.0 把原本约 40KB 的单体技能拆成「轻量主技能 + 5 个按需加载的子技能」，初始上下文占用下降约 80%。主技能只做三件事：初始化、意图路由、版本协调。

| 子技能 | 负责什么 | 典型触发 |
|---|---|---|
| `alaya-persona` | 角色选择、复制、回收、群组讨论、统一语言 | 「用费曼回答」「让几个角色讨论」「所有角色都用中文」 |
| `alaya-retrieval` | 总索引、类别索引、知识卡与交叉链接检索 | 「查我的知识库」「结合知识库解释」 |
| `alaya-import` | 批量导入、单篇收录、语义知识卡、质量检查 | 「导入这些资料」「收录这篇文章」 |
| `alaya-memory` | 回答后固定提交、共享状态与历史、用户档案、BI 观察 | 「记住这个偏好」「忘掉职业信息」 |
| `alaya-maintenance` | 动态索引、链接检查、衰减熏习、健康检查 | 「检查知识库」「预览重建索引」 |

激活模式为 `contextual`（上下文触发）：只有用户明确提到 Alaya、角色、知识库、记忆、导入、检索或维护意图时才介入，普通闲聊与通用问答不自动接管。

### （三）三层描述驱动知识图谱

```text
Layer 1 · wiki/index.md（约 1–2KB）
  类别 wikilink + 描述段落；LLM 读此文件把问题与类别做语义匹配

Layer 2 · wiki/{类别}/{类别}_category.md
  类别头部描述 + 「## Cards」区（卡片名 + 一行描述）；构建候选池

Layer 3 · wiki/{类别}/*.md
  知识卡本体，YAML 头含 description 字段；仅在角色选中后加载全文
```

关键设计：**描述本身就是图谱**。系统不再维护显式图边与标签交叠计算，跨类别关系以散文写进描述（如「与认知科学在注意力概念上交叉」），由 LLM 语义匹配自然发现。三层全部使用 `[[wikilinks]]`，因此知识库可直接作为 Obsidian vault 打开，用 Graph View 看到卡片与交叉引用。

### （四）知识卡格式

```markdown
---
seed_type: REFINED
created_by: system
strength: 0.5
last_activated: 2026-05-31
activation_count: 0
half_life: 30
tags: [deep-learning, transformer, attention]
description: "Transformer 架构通过自注意力机制实现了序列到序列的高效建模。"
---

# Transformer Architecture

正文内容……
```

卡片身份是「类别路径 + 文件名」，不是显示标题；内容哈希相同即视为重复，同名不同内容会生成稳定后缀，绝不覆盖旧卡。

### （五）核心机制

| 机制 | 作用 |
|---|---|
| 描述驱动检索 | 三层语义匹配替代显式图边与标签计算 |
| 卡片 description | YAML 中的一行摘要，让第二层无需加载全文即可匹配 |
| 类别头描述 | 从类别页的自动区块提取为索引摘要，可让智能体按「更新类别描述」重写 |
| 角色档案 | JSON 配置 + Markdown 人物小传（核心特质、说话习惯、对话示例） |
| 熏习 | 被引用则增强、长期不用则衰减；按日结算并去重 |
| 休眠与唤醒 | 低于阈值进入休眠并提示；话题重提时以基础强度唤醒 |
| 来源追溯 | 卡片记录来源文件或原始路径；原文缺失时明确标注，不伪造引用 |
| BI 观察员 | 被动观察需求、决策、表达、兴趣、协作、风险六方面，只观察不干预 |

### （六）记忆层：分层且有边界

| 文件 | 内容 | 边界策略 |
|---|---|---|
| `memory/<persona>_memory.json` | 角色私有记忆 | 仅该角色可见 |
| `memory/ambient.json` | 跨角色轻量近期环境 | 上限 64KB |
| `memory/shared/profile.json` | 经用户确认的稳定偏好 | 上限 128KB，冲突需确认替换 |
| `memory/shared/state.json` | 跨角色当前有效状态 | 上限 128KB，按主题覆盖而非追加 |
| `memory/shared/history.json` | 重要变化历史 | 热 20 / 冷 80 / 512KB，超限裁剪最旧 |
| `memory/bi_state.json`、`bi_notes.json` | BI 观察结论与事件 | 每域 20 条、总 200 条、180 天、状态文件不超过 256KB |

固定保存时机是**每次角色回答完成后**与**每次群组汇总完成后**，不猜测「会话是否即将结束」。写入使用唯一 `turn_id` / `group_id`，重试幂等：不重复增强卡片、不重复增长好感、不重复写记忆。

### （七）关键参数（`alaya/config.json`）

| 参数 | 默认 | 含义 |
|---|---|---|
| `knowledge.top_k` / `min_pool` | 3 / 10 | 默认取卡片数 / 候选池下限 |
| `knowledge.cold_after_days_default` | 90 | 卡片进入休眠的天数 |
| `knowledge.wake_strength` / `sleep_threshold` | 0.5 / 0.1 | 基础强度 / 休眠阈值 |
| `memory.hot_zone_size` / `cold_zone_size` | 5 / 45 | 记忆热区 / 冷区容量 |
| `memory.semantic_memory_enabled` | true | 是否启用回答后简短语义记忆 |
| `persona.default_persona` | feynman | 默认角色 |
| `persona.language_mode` | global | 统一语言（改顶层 `language` 一处生效） |
| `persona.affinity_decay` | 0.992 | 角色好感每日衰减 |
| `import.max_chars_for_extraction` | 8000 | 单文件抽取字符上限 |

关于衰减的两代口径：v2.x 采用「30 天半衰期」，约 67 天进入休眠；v3.1 收敛为唯一主参数「90 天从 0.5 衰减到 0.1」，每日衰减率由 `d = (0.1 / 0.5)^(1/90)` 反推，不再叠加互相矛盾的固定衰减率。首次升级只建立当天基线，不追溯补扣。

| 「把这批资料导进知识库」 | 批量导入，先给你一份零写入预览，你点头才真正落库 |
| 「把这篇文章收录一下」 | 单篇收录，生成一张完整知识卡 |
| 「帮我整理成知识卡」 | 它先读懂内容，再按卡片格式整理，而不是机械搬运原文 |
| 「这次把原文也存一份」 | 只有你这么说，才会把原文复制进知识库的原文目录 |
| 「检查这批卡片的质量」 | 只读体检：缺描述、缺来源、内容过短的卡片会被点出来 |

导入时它一定会追问一句：这次要不要把原文也存进知识库。这是每次都要单独回答的问题，不会沿用上次的选择。

### （四）记忆与偏好

| 你这样说 | 它会做什么 |
|---|---|
| 「记住我喜欢先给结论，再讲原因」 | 确认后写进共享偏好档案，所有角色都照着办 |
| 「你还记得我哪些偏好？」 | 列出已确认的偏好清单，附上来源与时间 |
| 「忘掉我的职业信息」 | 删掉这条偏好和它的变化记录 |
| 「这次不用记」 | 本轮对话不写记忆，只更新必要的机械状态 |
| 「以后别主动问我建档案」 | 记下拒绝状态，不再反复打扰 |

### （五）检查与维护

| 你这样说 | 它会做什么 |
|---|---|
| 「检查知识库」 | 只读体检：配置、角色、卡片、索引、原文引用、链接逐项过一遍 |
| 「预览重建索引」 | 先告诉你索引和磁盘差在哪，不动任何文件 |
| 「确认重建索引」 | 真的重建，并保证总索引覆盖全部类别 |
| 「检查坏链接」 | 只列报告，不擅自改你的文件 |
| 「修复链接的大小写错误」 | 只修那些唯一确定、不会误伤的链接 |
| 「现在熏习一次」 | 立刻结算一次知识强度与角色好感；平时它每天自己顺带做 |
| 「审视一下分类结构」 | 观察员角色检查类别是否过碎，给出合并建议 |

进阶说明：上面每一个说法背后都有对应的脚本命令，需要排查问题、写自动化任务时可以让智能体直接执行；日常使用则完全不必接触命令。

## 七、在 WorkBuddy 中怎么用

### （一）安装

对智能体说一句即可：「帮我安装这个技能：https://gitee.com/DL-LEO-gitee/alaya」。也可以手动把仓库放到技能目录 `C:\Users\sjlia\.workbuddy\skills\alaya`。

安装只校验技能文件，不替你创建知识库。装完可以让它自检一次，确认技能文件齐全；再确认知识库指针对准了你想要的文件夹（本机是 `D:\alaya-kb`），之后所有资料都读写在这一个文件夹里。

### （二）初始化

说「启用识海」或「初始化 Alaya」，智能体会依次询问六件事：

1. 知识库放在哪个本地硬盘（Windows 推荐 D 盘）。
2. 具体目录（推荐 `D:\alaya-kb`；若配合 Obsidian，可选中 vault 目录）。
3. 是否安装内置种子角色。
4. 是否启用「每次回答后保存简短语义记忆」（可关闭，单次也可说「这次不记」）。
5. 是否安装示例知识（默认否，且仅空 `wiki/` 可安装）。
6. 是否现在建立共享偏好档案（现在 / 以后 / 不要再问）。

已有 `alaya/config.json` 不会被静默覆盖；需要升级配置时先 `--migrate-config` 预览，再 `--apply-migration` 应用，应用前自动备份。

### （三）日常交互：说话就行

原则是：不需要记 Python 命令，说话就行。Alaya 采用上下文触发——不提到它，它不接管。

### （四）配合 Obsidian 看图谱

知识卡使用 `[[wikilinks]]`，与 Obsidian 完全兼容：把知识库根目录「Open folder as vault」，点右上角 Graph View，即可看到全部卡片与交叉引用的关系图。建议初始化时直接把 Obsidian vault 目录作为知识库根目录。

### （五）透明机制与已知问题

透明机制三点：熏习搭便车（每次提交后顺带做到期检查，按日去重）、幂等提交（同一事件标识重试不重复记账）、失败可见（记忆写入失败会明确告知，回答不撤回）。

| 现象 | 原因 | 处理 |
|---|---|---|
| unrecognized arguments | 用了旧版位置参数 | 索引统一用 `--kb-root` + `--category` |
| PDF 抽取报 DLL 加载失败 | 隔离运行时装 pymupdf 缺原生依赖 | 改用纯 Python 的 `pypdf` |
| 长文档只导入前几千字 | max_chars 默认 8000 | 配置调至 100000 |
| 批量导入后段卡片写不进 | PYTHONPATH 指向 shim 触发删除计数上限 | 先置空 PYTHONPATH 再执行 |
| 提示另一操作持有锁 | import.lock 残留 | 确认无进程占用后删除该锁文件 |

### （六）升级、备份与迁移

知识库是纯文本：整个文件夹复制、压缩、进 git 或网盘同步就是备份，不需要导出命令；卡片、记忆、角色都能直接读、直接改。升级技能只替换技能目录里的文件，用户知识库不动。新版本带来配置项变化时，先预览再应用，应用前会自动备份旧配置。

换电脑只需两步：装好技能，让知识库指针对准拷过去的文件夹。若旧库结构较老，先做一次只读体检，按报告逐项迁移，不要手工改索引文件。

## 八、能力边界与安全

**能做**：多角色问答与研讨、三层知识检索、资料导入与知识卡生成、有界长期记忆、索引与链接维护、衰减结算。

**不能做**：联网下载原文、完整知识图谱推理、向量语义检索、权限与加密管理、替代用户判断知识真伪。

安全约束（仓库根目录附有两份技能安全评估报告）：

1. 所有写入必须落在已解析的知识库根目录内，路径不得逃出知识库。
2. 写入前完整验证负载，采用临时文件原子替换；导入先生成零写入计划再提交。
3. 秘密信息（密钥、令牌、银行卡号）永不保存；年龄、性别、教育等身份字段不得由模型推断。
4. 角色移除为可恢复移动，永久清理需二次确认。
5. 健康检查与链接检查默认只读，写入动作需显式执行。

## 九、附：哲学四智

| 识 → 智 | 含义 | Alaya 实现 |
|---|---|---|
| 大圆镜智 | 阿赖耶识如实照见一切 | 种子库：无偏存储全部知识，等待激活 |
| 平等性智 | 末那识超越我执，平等视之 | 多角色检索：没有唯一正确视角，每个角度都有效 |
| 妙观察智 | 第六意识无执地观察 | 按角色推理：观察与诠释，不强迫一个真理 |
| 成所作智 | 前五识把行动转化为利益 | 熏习循环：每次交互留下痕迹，系统进化 |

> 知识不是存储，是生命。Alaya 的目标不是完美检索，而是让存储在库里的「识」，通过持续的熏习，逐步长成多视角的「智」。
